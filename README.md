# DroneVision

DroneVision — програма для перегляду та запису відео з IP-камери, роботи з OSD і телеметрією, а також зчитування каналів пульта. Програма призначена для Windows і постачається готовим інсталятором.

## Можливості

- Перегляд відео з камери через RTSP.
- Профілі пристроїв для швидкого перемикання між камерами та RTSP-адресами.
- Налаштування відеопотоку: транспорт, затримка та корекція зображення.
- Запис RTSP-відео або зображення екрана; вибір папки та обмеження обсягу записів.
- Приймання MSP DisplayPort/OSD від камери через UDP і відображення накладання поверх відео.
- Налаштування видимих елементів OSD, їхнього розташування, шрифту та розміру.
- Зчитування каналів сумісного джойстика, перегляд RC-значень і калібрування.
- Керування через Mission Planner або пряме передавання RC-каналів через MAVLink — залежно від обраного режиму.
- Вбудований термінал для локальних команд Windows або SSH-підключення до камери.
- Темна та світла теми, рядок стану з інформацією про відео, джойстик і телеметрію.

## Завантаження та встановлення

1. Відкрийте [сторінку останнього релізу](https://github.com/Pasichnyk100/DroneVision-Releases/releases/latest).
2. Завантажте файл `DroneVision-...-Setup.exe` з розділу **Assets**.
3. Запустіть інсталятор і дозвольте внесення змін, коли Windows покаже запит адміністратора. Інсталятор додає правила брандмауера для UDP-портів `14550` і `14551`.
4. Після встановлення запустіть DroneVision із меню «Пуск» або ярлика.

Під час першого запуску програма може відкриватися довше, ніж очікується: дочекайтеся появи головного вікна й не запускайте кілька копій одночасно.

Інсталятор містить необхідні компоненти програми та FFmpeg. Окремо встановлювати Python чи GStreamer для роботи встановленої версії не потрібно.

Якщо комп’ютер керується політиками організації й Windows не дозволяє додати локальні правила брандмауера, попросіть адміністратора дозволити вхідний UDP-трафік на порти `14550` і `14551` для потрібних мережевих профілів. Не потрібно вимикати брандмауер повністю.

## Перший запуск

1. Відкрийте **Налаштування → Відеопристрої** та створіть або виберіть профіль камери.
2. Укажіть повну RTSP-адресу, наприклад `rtsp://адреса-камери:554/шлях`. Якщо камера вимагає авторизацію, заповніть поля логіна й пароля профілю.
3. Під’єднайте джойстик до комп’ютера перед запуском програми. За потреби перевірте, що Windows його бачить, у системному засобі `joy.cpl`.
4. Натисніть кнопку запуску RTSP. Статуси відео, MSP, MAVLink і джойстика відображаються внизу головного вікна.

## Підключення камери та телеметрії

Камера й ноутбук мають бути доступні один одному через локальну мережу, ZeroTier, WireGuard або інше налаштоване з’єднання. У камері файл `/etc/telemetry.conf` містить налаштування MAVLink та MSP/OSD. Нижче наведено повний приклад:

```ini
#########################
# MAVLink
MAV_ENABLE=1
MAV_DEV="/dev/ttyS2"
MAV_BAUD="115200"

# Тут вкажіть IP ноутбука у ZeroTier, WireGuard або іншій мережі
MAV_REMOTE_IP="IP-АДРЕСА-НОУТБУКА"
MAV_REMOTE_PORT="14550"

MAV_LISTEN_IP="0.0.0.0"
MAV_LISTEN_PORT="14550"

# MSP / OSD
MSP_ENABLE=1
MSP_DEV="/dev/ttyS0"
MSP_BAUD="115200"
MSP_COLS="8"
MSP_RATE="20"
MSP_SIZE="1280x720"

# Та сама IP-адреса ноутбука; DroneVision приймає MSP на UDP 14551
MSP_UDP="IP-АДРЕСА-НОУТБУКА:14551"

#########################
```

Замініть `IP-АДРЕСА-НОУТБУКА` на адресу ноутбука у мережі, якою користуєтесь. Впишіть її у два рядки: `MAV_REMOTE_IP` та `MSP_UDP`. Наприклад, якщо адреса ZeroTier ноутбука `12.49.86.96`, рядки матимуть вигляд:

```ini
MAV_REMOTE_IP="12.49.86.96"
MSP_UDP="12.49.86.96:14551"
```

Для ZeroTier використовуйте IP ZeroTier, а для WireGuard — адресу WireGuard, а не обов’язково адресу Wi-Fi. У наведеному прикладі порт MSP має бути `14551`, бо саме його слухає DroneVision. Якщо у вашому файлі зараз `MSP_UDP="127.0.0.1:14550"`, замініть і `127.0.0.1` на IP ноутбука, і порт `14550` на `14551`.

Змінити адресу можна вручну в `/etc/telemetry.conf` або через термінал DroneVision: виберіть SSH-профіль камери, підключіться, натисніть **Редагувати telemetry.conf**, введіть IP ноутбука та підтвердьте. Кнопка автоматично змінює IP у `MAV_REMOTE_IP` і `MSP_UDP`; переконайтеся, що порт після адреси в `MSP_UDP` дорівнює `14551`.

DroneVision приймає MSP/OSD на UDP `14551`, а MAVLink — на UDP `14550`. Для відображення OSD камера має передавати сумісні MSP DisplayPort-пакети. Якщо пакетів немає, перевірте IP і порти в конфігурації камери, мережевий маршрут і правила брандмауера.

## Відео, OSD і джойстик

### RTSP-відео

Керуйте потоком кнопками запуску та зупинки RTSP. Налаштування транспорту й затримки доступні у параметрах відео. Запис відеопотоку та запис екрана — різні режими: перший зберігає початкове відео, другий — зображення екрана разом із видимим OSD.

### OSD

Пункт **OSD** дає змогу показати або приховати накладання та налаштувати його вигляд. Дані OSD надходять від камери через MSP DisplayPort. До отримання таких пакетів програма не може показати живі дані з польотного контролера.

### Джойстик і керування

Кнопка **RC** відкриває панель каналів. У ній можна переглянути значення каналів і відкрити калібрування. Передавання RC-команд увімкнене лише в режимі прямого керування та після окремого ввімкнення в меню RC. Якщо вибрано режим через Mission Planner, керування виконується через нього.

## Ліцензія

Під час першого запуску доступний безкоштовний пробний період тривалістю **3 дні**. Після його завершення для подальшої роботи потрібна ліцензія, видана для ID цього комп’ютера. Скопіюйте ID із вікна ліцензії та передайте його розробнику, а отриманий файл `.dvlic` активуйте в програмі кнопкою завантаження ліцензії.

## Оновлення

У вікні **Інфо** натисніть **Перевірити оновлення**. Якщо доступна новіша версія, програма покаже інформацію та посилання на завантаження. Сам інсталятор запускається користувачем окремо.

## Журнал і підтримка

Журнал програми зазвичай зберігається тут:

```text
%LOCALAPPDATA%\DroneVision\Logs\dronevision.log
```

Для звернення відкрийте **Інфо → Написати розробнику** або скористайтеся [формою підтримки](https://dronevision-support.pasichnyk100.workers.dev/). Повідомлення з форми публікуються як GitHub Issue і можуть бути видимі іншим людям. Якщо додаєте журнал, спершу перегляньте його та вилучіть паролі, приватні IP-адреси й інші дані, які не хочете оприлюднювати.
